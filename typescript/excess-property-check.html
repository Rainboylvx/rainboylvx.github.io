这是 TypeScript 里最让人困惑的规则之一：同样的对象，直接写字面量会报错，先存变量就不报错。

规则本身

 1// 多余属性检查：对象字面量的特殊规则
 2
 3interface Point { x: number; y: number }
 4
 5// ---- 直接赋字面量：检查多余属性 ----
 6// @ts-expect-error TS2353: Object literal may only specify known properties
 7const p1: Point = { x: 1, y: 2, z: 3 };
 8
 9// ---- 先存变量再赋值：不检查 ----
10const raw = { x: 1, y: 2, z: 3 };
11const p2: Point = raw;        // ✓ 通过！z 被忽略
12
13// 为什么？因为 raw 的类型是 { x: number; y: number; z: number }，
14// 它结构上满足 Point（多出的属性不影响赋值兼容性）
15
16// ---- 函数参数：同样规则 ----
17function draw(p: Point): string { return `${p.x},${p.y}`; }
18
19draw({ x: 1, y: 2 });         // ✓
20// @ts-expect-error TS2353: 字面量直接传，会检查
21draw({ x: 1, y: 2, z: 3 });
22
23const withZ = { x: 1, y: 2, z: 3 };
24draw(withZ);                  // ✓ 通过变量传，不检查
25
26// ---- 中间变量类型注解能"洗掉"多余属性 ----
27const typed: Point = { x: 1, y: 2 };
28draw(typed);                  // ✓
29
30// ---- 索引签名会关闭多余属性检查 ----
31interface WithIndex {
32  x: number;
33  [key: string]: unknown;
34}
35const p3: WithIndex = { x: 1, anything: "ok" };   // ✓ 索引签名允许
36
37// ---- 联合类型的多余属性检查 ----
38type A = { kind: "a"; a: number };
39type B = { kind: "b"; b: number };
40
41// @ts-expect-error TS2353: kind 匹配 A，但 a/b 混了
42const mixed: A | B = { kind: "a", b: 1 };
43
44// 正确写法
45const okA: A = { kind: "a", a: 1 };
46const okB: B = { kind: "b", b: 1 };
47
48// ---- 空对象类型 {} 不检查 ----
49const anyObj: {} = { anything: 1, more: "x" };    // ✓ 因为 {} 没有已知属性
50
51// ---- 数组与元组 ----
52interface Item { id: number }
53// @ts-expect-error TS2353: 数组元素是字面量，会检查
54const items: Item[] = [{ id: 1, extra: true }];
55const itemsRaw = [{ id: 1, extra: true }];
56const items2: Item[] = itemsRaw;    // ✓ 通过变量
57
58console.log(p1, p2, draw(withZ), typed, p3, okA, okB, anyObj, items, items2, mixed);

1{ x: 1, y: 2, z: 3 } { x: 1, y: 2, z: 3 } 1,2 { x: 1, y: 2 } { x: 1, anything: 'ok' } { kind: 'a', a: 1 } { kind: 'b', b: 1 } { anything: 1, more: 'x' } [ { id: 1, extra: true } ] [ { id: 1, extra: true } ] { kind: 'a', b: 1 }

 1interface Point { x: number; y: number }
 2
 3// 直接赋字面量：报错
 4const p1: Point = { x: 1, y: 2, z: 3 };
 5// error TS2353: Object literal may only specify known properties, and 'z'
 6// does not exist in type 'Point'.
 7
 8// 先存变量：通过
 9const raw = { x: 1, y: 2, z: 3 };
10const p2: Point = raw;      // ✓

同样的规则适用于函数参数：

1function draw(p: Point): string { }
2
3draw({ x: 1, y: 2, z: 3 });   // ✗ 字面量直接传，检查
4const withZ = { x: 1, y: 2, z: 3 };
5draw(withZ);                  // ✓ 变量传，不检查

为什么会这样

两个原因：

原因一：结构类型系统。 TypeScript 是结构类型——只要对象的形状满足目标类型就够了。{ x, y, z } 满足 Point（有 x 和 y），多出的 z 不影响兼容性。

原因二：拼写错误防护。 如果字面量直接写，多出来的属性很可能是拼错了：

1const typo: Point = { X: 1, y: 2 };
2// error TS2561: Object literal may only specify known properties, but 'X' does
3// not exist in type 'Point'. Did you mean to write 'x'?

所以这个检查只针对字面量，因为只有字面量才能可靠地推断"用户是不是写错了"。一旦经过变量，TypeScript 无法判断那个变量是有意构造的还是有 bug，就放弃检查。

记住这个说法

多余属性检查是**“新鲜对象字面量检查”**（fresh object literal check）。它只作用于"新鲜"的字面量——刚写出来、还没被赋给任何变量、也没经过类型注解的字面量。

什么会关闭这个检查

情况是否检查
直接写字面量✓ 检查
先存变量✗ 不检查
通过函数返回值✗ 不检查
对象展开 {...base}✗ 不检查
类型有索引签名✗ 不检查
目标类型是 {}✗ 不检查
类型断言 as✗ 不检查
1// 索引签名关闭检查
2interface WithIndex {
3  x: number;
4  [key: string]: unknown;
5}
6const p3: WithIndex = { x: 1, anything: "ok" };   // ✓
7
8// {} 没有已知属性，所以任何字面量都满足
9const anyObj: {} = { anything: 1, more: "x" };    // ✓

数组里的元素也是字面量，同样检查：

1const items: Item[] = [{ id: 1, extra: true }];   // ✗ 检查
2const raw = [{ id: 1, extra: true }];
3const items2: Item[] = raw;                        // ✓ 不检查

联合类型下的行为

1type A = { kind: "a"; a: number };
2type B = { kind: "b"; b: number };
3
4const mixed: A | B = { kind: "a", b: 1 };
5// error TS2353: Object literal may only specify known properties, and 'b'
6// does not exist in type 'A'.

错误说的是 A——因为 kind: "a" 已经确定了它应该是 A，然后 b 就成了多余属性。

绕过的四种方式

 1// 绕过多余属性检查的四种方式
 2
 3interface Point { x: number; y: number }
 4
 5// ---- 方式 1：中间变量（最简单，但会丢失字面量检查）----
 6const raw = { x: 1, y: 2, z: 3 };
 7const p1: Point = raw;
 8
 9// ---- 方式 2：类型断言（明确表达"我知道有额外属性"）----
10const p2: Point = { x: 1, y: 2, z: 3 } as Point;
11
12// 更精确的断言：保留额外属性的类型信息
13const p3 = { x: 1, y: 2, z: 3 } as Point & { z: number };
14const zValue = p3.z;           // z 可访问
15
16// ---- 方式 3：索引签名（如果类型本来就允许额外键）----
17interface PointWithExtra {
18  x: number;
19  y: number;
20  [key: string]: unknown;
21}
22const p4: PointWithExtra = { x: 1, y: 2, z: 3 };   // ✓ 无需绕过
23
24// ---- 方式 4：泛型函数（保留具体类型）----
25// 常见的"接受更宽输入但返回精确类型"模式
26function createPoint<T extends Point>(p: T): T {
27  return p;
28}
29const p5 = createPoint({ x: 1, y: 2, z: 3 });   // T = { x: 1; y: 2; z: 3 }
30const p5z = p5.z;                               // ✓ 保留 z
31
32// 对比：不泛型时，返回值丢失额外属性
33function createPointPlain(p: Point): Point { return p; }
34const p6 = createPointPlain({ x: 1, y: 2, z: 3 } as Point);
35// p6.z 报错：Point 上没有 z
36
37// ---- 什么时候该"绕过" ----
38// 场景：把更宽的对象传给只需要部分字段的函数
39interface User { id: number; name: string; email: string }
40function sendEmail(u: Pick<User, "name" | "email">): string {
41  return `to ${u.name} <${u.email}>`;
42}
43
44const fullUser: User = { id: 1, name: "a", email: "b" };
45sendEmail(fullUser);           // ✓ 变量传参，不检查多余属性
46
47// 但直接传字面量会报错
48// @ts-expect-error TS2353: id 是多余的
49sendEmail({ id: 1, name: "a", email: "b" });
50
51// 正确做法：传变量，或者显式构造需要的形状
52sendEmail({ name: "a", email: "b" });
53
54// ---- 一个实用的判断标准 ----
55// 多余属性检查是"防止拼写错误"的保护机制
56// 如果多余的属性是**有意**的（如展开对象），绕过是对的
57// 如果是**拼写错误**，绕过会掩盖 bug
58
59const base = { x: 1, y: 2 };
60const withZ = { ...base, z: 3 };     // 展开后的对象
61const p7: Point = withZ;             // ✓ 不检查，这是预期的
62
63// @ts-expect-error TS2561: 拼写错误（x 写成了 X），应该被抓住
64const typo: Point = { X: 1, y: 2 };
65
66console.log(p1, p2, p3, zValue, p4, p5, p5z, p6, sendEmail(fullUser), p7, typo);

1{ x: 1, y: 2, z: 3 } { x: 1, y: 2, z: 3 } { x: 1, y: 2, z: 3 } 3 { x: 1, y: 2, z: 3 } { x: 1, y: 2, z: 3 } 3 { x: 1, y: 2, z: 3 } to a <b> { x: 1, y: 2, z: 3 } { X: 1, y: 2 }

方式一：中间变量

1const raw = { x: 1, y: 2, z: 3 };
2const p1: Point = raw;

最简单，但会丢失字面量检查——拼写错误也不会被抓到。

方式二：类型断言

1const p2: Point = { x: 1, y: 2, z: 3 } as Point;
2
3// 更精确：保留额外属性的类型
4const p3 = { x: 1, y: 2, z: 3 } as Point & { z: number };
5p3.z;    // ✓ 可访问

断言明确表达了"我知道有额外属性"，比中间变量更清晰地传达了意图。

方式三：索引签名

如果类型本来就允许额外键，直接加索引签名：

1interface PointWithExtra {
2  x: number;
3  y: number;
4  [key: string]: unknown;
5}
6const p4: PointWithExtra = { x: 1, y: 2, z: 3 };   // ✓ 无需绕过

方式四：泛型函数

需要"接受宽输入但保留精确类型"时：

1function createPoint<T extends Point>(p: T): T {
2  return p;
3}
4
5const p5 = createPoint({ x: 1, y: 2, z: 3 });   // T = { x: 1; y: 2; z: 3 }
6p5.z;    // ✓ 保留了 z

对比不泛型的版本，额外属性会丢失：

1function plain(p: Point): Point { return p; }
2const p6 = plain({ x: 1, y: 2, z: 3 } as Point);
3// p6.z 报错：Point 上没有 z

实用场景：把宽对象传给窄参数

这是最常见的"该不该绕过"的场景：

 1interface User { id: number; name: string; email: string }
 2
 3function sendEmail(u: Pick<User, "name" | "email">): string { }
 4
 5const fullUser: User = { id: 1, name: "a", email: "b" };
 6sendEmail(fullUser);              // ✓ 变量传参，不检查多余属性
 7
 8sendEmail({ id: 1, name: "a", email: "b" });
 9// error TS2353: 'id' 是多余的
10
11sendEmail({ name: "a", email: "b" });   // ✓ 显式构造需要的形状

判断标准

多余属性检查是防止拼写错误的保护机制。绕过之前先问：多出来的属性是有意的还是笔误？

1// 有意的：对象展开
2const base = { x: 1, y: 2 };
3const withZ = { ...base, z: 3 };
4const p7: Point = withZ;      // ✓ 不检查，符合预期
5
6// 笔误：应该被抓住
7const typo: Point = { X: 1, y: 2 };
8// error TS2561: Object literal may only specify known properties, but 'X' does
9// not exist in type 'Point'. Did you mean to write 'x'?
不要用中间变量"掩盖"错误

const raw = {...}; const p: Point = raw; 这个套路很方便，但它同时关掉了拼写检查。如果你只是想快速让编译通过，可能会把真正的 bug 藏起来。

更好的做法是显式构造需要的形状，或者用 as 明确表达意图。
