不同用途对随机数的要求不一样

游戏骰子关注分布是否合理；协议 nonce 还需要满足协议规定的唯一性或不可预测性；长期密钥涉及足够熵、秘密存储和完整安全设计。不能因为串口输出“看起来很乱”，就断言它适合生成密钥。

ESP32-S3 的随机数保证与硬件熵源状态有关。本例在没有 ADC、Wi-Fi、蓝牙活动的独立工程中，通过 bootloader_random_enable() 临时启用内部熵源，采样结束后 disable。不要把这段初始化直接搬进已有无线或 ADC 任务的综合程序。具体约束以官方随机数文档和目标芯片为准。

为什么 random % 6 存在微小偏差

32 位无符号数共有 2^32 种，不能被 6 整除，余数是 4。直接取模时，有几个点数会比其他点数多对应一个输入。

代码计算 limit = -bound % bound，无符号运算下 bound=6 时得到 4；遇到 0～3 重新取样，剩余区间大小可被 6 整除，再对 6 取模。这里要求 bound>0，示例固定为 6。

统计实验能证明什么，不能证明什么

程序取 6000 次样本，打印各点数次数。每个点数大约接近 1000，但不应恰好等于 1000，也不要求各次运行得到不同的每一个字节。有限样本只用于理解分布，不能证明加密安全。

打印的 16 个随机字节是演示数据，绝不能把真实密钥或身份凭证照此输出日志。工程每 100 次让出一次 CPU，避免把随机数统计写成长期独占核心的循环。

工程如何组织

本例围绕一个系统外设展开，先在 main/main.c 中按顺序展示完整调用过程；可复用的多设备驱动在后续工程中放到 components/BSP/。不要把芯片驱动的初始化藏在无法看到的外部脚本里。

应用代码：入口与处理流程

下面代码直接取自配套工程的 main/main.c，头文件和 BSP 实现在仓库中一并提供。初学时先看 app_main()，再追踪它调用的模块。

 1#include <stdio.h>
 2#include <stdint.h>
 3#include <stdbool.h>
 4#include <string.h>
 5#include <stdlib.h>
 6#include <assert.h>
 7#include "esp_err.h"
 8#include "esp_log.h"
 9#include "esp_timer.h"
10#include "freertos/FreeRTOS.h"
11#include "freertos/task.h"
12#include "esp_random.h"
13#include "bootloader_random.h"
14// 拒绝采样消除直接取模的偏差，bound 必须大于 0。
15static uint32_t uniform(uint32_t bound)
16{
17    uint32_t limit=-bound%bound,r;
18    do { r=esp_random(); } while(r<limit);
19    return r%bound;
20}
21void app_main(void)
22{
23    // 本例独占内部 ADC 熵源；不要与 ADC、Wi-Fi、蓝牙示例同时运行。
24    bootloader_random_enable();
25    uint8_t bytes[16];
26    esp_fill_random(bytes,sizeof(bytes));
27    ESP_LOG_BUFFER_HEX("random_demo",bytes,sizeof(bytes)); // 仅演示字节，绝不能打印真实密钥。
28    unsigned bins[6]={0};
29    for(int i=0;i<6000;i++) {
30        bins[uniform(6)]++;
31        if(i%100==0) vTaskDelay(pdMS_TO_TICKS(1));
32    }
33    bootloader_random_disable(); // 停止内部熵源后，不再声称后续输出有同等熵保证。
34    for(int i=0;i<6;i++) ESP_LOGI("dice","face=%d count=%u",i+1,bins[i]);
35}
